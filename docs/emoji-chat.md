# 图片表情与 Unicode emoji

聊天框左侧“表情”面板包含历史记录、我的收藏、全部表情和上传图片。

- 本地 PNG/JPG 先预览，点击“上传并发送”后通过统一入口上传到 Gitee；最长边缩小至 512 像素，PNG 超过 256 KiB 时再缩至 256 像素。拒绝超过 16 MiB、8192 单边或 1600 万像素的源图，暂不支持动图。上传后匿名读取直链并核对 SHA256，成功后才发送 `[pic]URL[/pic]`；失败保留预览，可重试。
- 鼠标悬停表情或本地图片预览时，在菜单上层显示大图。列表仍使用 128 像素缩略图，悬停时单独读取最长边 512 像素的大图，仅保留一张大图缓存；离开图片后收起。
- 表情面板保留顶部四页导航；标题栏、收起按钮与其他窗口共用样式，导航区和内容区采用相同的分层灰色背景。输入框和悬停预览沿用主菜单的字体、20 号字号、圆角样式、菜单文字配色和全局缩放设置；拖动标题栏可调整面板位置。
- ☆ 收藏和 ★ 取消收藏；收藏与历史分开保存，清空历史不删除收藏。三个表情列表支持名称/链接搜索，内置重复链接合并显示。自定义直链可从上传页加入收藏，兼容 Gitee `/blob/` 文件页和日志中的 `https\://`。
- 每个客户端独立上传，默认使用内置 HTTPS 上传入口，无需 Gitee 登录、令牌、房主许可或专用网络协议。客户端先把图片提交到上传服务，服务端将图片写入 Gitee 并返回公开直链；最终仅发送原有 `[pic]URL[/pic]` 聊天内容。房主和其他玩家只需已有 Mod 能解析该格式，发送端的新功能不会增加接收端版本要求。
- 上传入口为 `https://download.mc1.top/api/emoji/upload`，位于现有下载服务器，Gitee 仓库级令牌仅保存在服务器的专用配置中。服务只接受 ≤256 KiB、尺寸 ≤512×512 的 PNG，解码重编码去除元数据，校验公开直链后返回 URL/摘要；并发与频率限制用于控制上传资源占用，不要求玩家注册或登录。
- 客户端不含图床设置、自定义仓库或令牌读写逻辑。收藏位于 `YxMod/emoji-favorites.json`，使用字符串数组兼容当前受保护注入程序集的 Unity JSON 序列化。
- 打开面板时，聊天输入暂停接收按键，避免搜索时误发聊天；Esc 或右上角 × 关闭并返回聊天输入。

全景图管理提供“上传分享、复制链接、打开预览”：

- 选中的本地 PNG 通过独立的 `/api/panorama/upload` 上传到相同 Gitee 仓库的 `panorama/` 目录，保留原始像素和 2:1 比例，支持最大 8192×4096、32 MiB。截图不会自动上传。
- 分享链接打开现有 `https://yxmod.cc/panorama.html` 360° 预览页。图片经过只允许内容哈希路径的只读转发入口，提供 WebGL 所需跨域响应；Gitee 凭据不会发往浏览器。
- 分享记录保存在原 PNG 旁的 `.share.json` 文件，记录原文件长度和修改时间。重新进入管理页可直接复制链接/预览；原文件改变后旧记录失效。原始 PNG 保留不动。

验证：`tools/x64/test-emoji-media.ps1` 检查链接和图片边界；`test-emoji-media-game.ps1` 在隔离 Unity 目录检查受保护 DLL 的图像、界面与悬停大图层级，以及表情和全景图实际上传及分享记录。传入 `-SkipUploads` 可只运行本地渲染和界面检查。`tests/test_emoji_service.py` 检查服务端尺寸、原像素保留、元数据清理、存储隔离、摘要和预览转发。服务源码与 systemd/Nginx 配置位于 `tools/emoji-service/`；`deploy-emoji-service.py` 复用服务器已有私有凭据部署，客户端无需任何图床配置。


## 游戏与 Mod 界面 Unicode emoji

当前 x64 聊天、头顶名字、Mod 界面，以及游戏本体的文字界面共用 Unicode 字素边界与离线图片。游戏的 Esc 信息栏、房间/玩家列表、菜单、提示、创意工坊信息和文字输入框通过对应的 Text、TextMeshPro、IMGUI、TextMesh 通用入口覆盖。通过系统 emoji 面板、输入法或粘贴输入；现有图片表情和游戏内原有图标照常使用。

- 图片固定为 Twemoji 17.0.3，Unicode 数据固定为 17.0：3,953 张原始 72px 图片、5,225 个序列映射、6 张 2048px 分页图集。完整离线资源随 EXE/ZIP 提供；PNG 位于独立的 `YxModAssets-x64.dll`，按内容哈希缓存在 `.yxmod-x64/assets/<hash>/`，普通代码更新不会重复下载。缺失或损坏时由游戏后台直接从 OSS/GitHub/镜像补齐，不依赖更新器；完成后刷新已有文本。详见 [资源下载与清单](x64-update-assets.md)。
- 额外按 Unicode 17.0 的 [emoji-variation-sequences.txt](https://www.unicode.org/Public/17.0.0/ucd/emoji/emoji-variation-sequences.txt) 识别 371 个允许变体选择符的字符。补齐 `♊️` 等 152 个默认彩色字符附加 VS16 后的单字符漏项，同时支持已收录肤色、ZWJ 组合中注册的 VS16；只在查找图片时规范化，原文、光标和选区索引保持不变。VS15 仍显示文字，未知组合不拆开匹配。派生属性与来源哈希留在代码包，PNG 包无需更新。
- 图集按使用解码、共享且不保留可读 CPU 副本；每页 RGBA32 显存约 16 MiB，六页上限约 96 MiB。退出时释放。
- 肤色、旗帜、键帽和 ZWJ 组合按完整字素编辑。VS15 使用文字形式；文字默认符号没有 VS16 时保留文字。未收录序列保留原文，不拆分成多张 emoji 图片。
- 光标、选区、退格、Delete、复制剪切、粘贴及长度截断使用原文索引与完整字素边界。输入法组合文字仅预览；候选提交用的回车不会同时发送聊天。
- 文字颜色与字号等样式保留；emoji 保留原色并跟随字号与透明度。网络及 UTF-8 日志保留原始 Unicode，旧客户端的显示取决于其字体/渲染能力。
- 历史正文支持拖选、Shift 扩选、Ctrl+A、Ctrl+C，复制得到原始文字。
- 旧版 3D 头顶名字使用 TextMesh 原生 inline quad，新版 UI 名字使用混排组件。16 字限制按完整字素计数，保留富文本闭合、背景宽度、显示隐藏、朝向、缩放和原有淡入淡出控制。
- `NameTagDepth` 为普通名字和 emoji 名字分开原版共面的文字与背景：背景沿本地 Z 轴放到文字后方至少 0.01，重复接入不累加偏移。保留原版 `NameTagBG` 的 `Unlit/Color NonZ` 材质、深度写入、颜色和 2999 队列，避免后绘制的天空/水面覆盖背景；文字和 emoji 沿用 LEqual 场景遮挡。没有新增背景材质。
- Mod 和游戏原生 IMGUI 的标签、按钮、窗口标题、提示框、选择网格、GUILayout 文字和普通输入框支持 emoji；菜单渐变颜色也按完整字素处理。无 emoji 的控件保持原生绘制，密码输入保持原生逻辑。
- 普通 UI Text 保留原组件引用、原文、Outline/Shadow、布局与按钮回调；文字顶点在原组件生成，emoji 使用子级图集批次。沿用字体家族、对齐、换行、行距、字号自适应、截断、父级遮罩与透明度。带有 emoji 的组件按需创建适配器，普通文本恢复原生网格。
- TextMeshProUGUI 和 3D TextMeshPro 使用原生 sprite fallback、原生换行/自动缩放/溢出/遮罩。内部解析缓冲采用不能与 Unicode 或游戏控制器图标冲突的临时代码，外部 text 属性与存档仍保留原文；可见字符索引还原为原始 UTF-16 索引。emoji 保留 RGB 原色，原有 `<sprite>` 标签继续可用。
- TMP_InputField 保留原生焦点、鼠标选择、多行、滚动、提交、取消和 IME 流程；左右移动、删除、选区替换、粘贴与长度限制使用完整字素。补齐旧字体拒收代理对的问题，尚未配对的高代理项暂存。数字、密码和自定义校验输入框保留原有规则。
- 游戏或地图创建的普通 InputField 使用共用编辑适配器，支持多行换行/纵向滚动，单行确认继续触发原有 end-edit 回调；聊天输入仍使用其聊天发送逻辑。场景普通 TextMesh 通过共享图集 inline quad 显示 emoji；新出现的地图组件在周期发现后接入，头顶名字仍使用专用即时更新路径。
- 动态字体沿用原字体家族创建独立图集，避免游戏原生 GUI/3D 文本刷新共享字形时造成漏绘；静态字体沿用原图集。按字号及样式预载、保留已请求字形，字体图集刷新后重新布局；原生窗口延后执行的正文也继承 Mod 作用域。退出时释放新增动态字体。
- IMGUI 的同行同样式文字合并绘制，避免逐字调用旧字体生成器；选区仍按原文字素边界绘制，复制保留原文。
- Mod 单行输入框只在 Repaint 使用真实宽度调整横向滚动；Layout/Used 的占位矩形不改变光标视口。短文本不滚动，长文本滚动限制在实际溢出范围，缩短或替换文本后自动恢复。
- 新增字体、UI mesh 及 IMGUI 渲染适配层通过声明式规则排除 Reactor 的 `hidemethods` 动态代理，以兼容旧 Mono 的结构体调用；其他保护保留。规则语法见 [Reactor 官方说明](https://www.eziriz.com/help/definitions/declarative_protection/)。

重建资源：`python tools/build-emoji-assets.py`（Pillow、requests）。来源、源文件 SHA-256、CC BY 4.0 图片许可和 Unicode 许可保存在 `YxModDll/Mod/Emoji/UnicodeAssets`；原文索引/字素元数据与许可留在 Mod DLL，图集与许可也嵌入独立资源 DLL。普通 Release 构建会自动构建资源程序集，计算其哈希并绑定到 Mod；只改代码不改变资源版本。

验证入口：

- `tools/x64/test-emoji.ps1`：完整资源覆盖、官方 GraphemeBreakTest、编辑边界、混排、独立资源图集哈希，以及 Mod DLL 不再包含 PNG 的检查。
- `tools/x64/test-emoji-mono.ps1`：使用本机游戏自带的 Mono x64 运行同一组测试及聊天 Rect 尾调用回归。
- `tools/x64/test-emoji-game.ps1`：显式启动的真实 Unity 渲染检查。要求游戏已退出；临时入口运行受保护 DLL、生成截图并退出，随后恢复原 DLL，清理入口与路径标记。结果在 `artifacts/x64/emoji-game-smoke.*`。

真实 Unity 自动检查还包括 LevelInformationBox 的 Text 引用、普通 UI 字号自适应、地图 TextMesh、3D TMP、全部 3,953 张图的 TMP sprite 映射、原有图标共存、TMP 原文索引、编辑和长输入滚动。菜单覆盖依据实际组件通用入口及自动场景夹具；未逐一手动打开每个菜单验收。实际系统 emoji 面板/输入法候选交互、跨机器收发仍需操作验收。

头顶名字检查使用游戏原版预制体与材质，覆盖三种文字、16/24 位深度、三个距离与三个角度，共 54 个视角；另复现旧版背景在后绘制天空前消失、被不透明人物材质遮住天空时重新出现的表现，并验证修正后背景完整及前景遮挡保留。场景检查使用不透明材质代理，未替代用户多人房间的实际验收。

同一 Unity 入口还验证背人/无碰撞回归：`HumanCollision.Set` 按最近的 `Human` 父组件筛选碰撞体，防止被背者的肢体混入背负者分组；全员无碰撞与功能面板共用此处理。测试通过原生 PhysX 球体接触观察碰撞开关，复现旧递归调用改动被背者自身碰撞对，再检查三人嵌套及五次背起/放下、禁用碰撞/运动学切换后的自身碰撞关系和玩家间碰撞。此夹具不包含真实角色关节、手臂动画或联网操作。
